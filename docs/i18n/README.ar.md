## نبذة عن المشروع

PWDnow هو مدير كلمات مرور مبني على فكرة بسيطة: لا يجب أن يرى الخادم، ولا المتصفح، ولا الشبكة بينهما، أي سر بصيغة نصية واضحة على الإطلاق. تُنفَّذ جميع العمليات التشفيرية داخل خدمة مخصصة مكتوبة بلغة Rust، مثبتة على نفس الجهاز الذي تُخزَّن فيه الخزنة. واجهة الويب، سواء فُتحت محليا أو قُدِّمت لمتصفح، لا تتبادل مع تلك الخدمة سوى كتل بيانات مشفرة معتمة. لا توجد مزامنة سحابية افتراضيا، ولا أي تتبع، ولا أي مزود يمكن إجباره على تسليم بياناتك، لأنه ببساطة لا يمتلكها أبدا.

ينقسم المشروع إلى طبقتين تتواصلان عبر قناة اتصال محلية بين العمليات:

- **خدمة الخزنة** (`daemon/`)، مكتوبة بلغة Rust: اشتقاق المفاتيح، التشفير، فك التشفير، التخزين عبر SQLCipher، تأمين الذاكرة، والمحو الآمن. هذا هو الجزء الوحيد في النظام الذي يتعامل مع مفتاح أو بيانات اعتماد بصيغة واضحة.
- **واجهة الويب** (`web/`)، تطبيق صفحة واحدة مبني بـ React 19 ويُقدَّم عبر عملية Express: تعرض الواجهة، وتُمرِّر الطلبات المشفرة إلى الخدمة عبر مقبس يونكس، ولا تحتفظ أبدا بأي مادة مفتاحية خارج رمز جلسة قصير الأجل، يُحفظ في الذاكرة فقط.

يمكن لـ PWDnow العمل بشكل كامل دون اتصال بالإنترنت على جهاز واحد، أو نشره خلف Nginx مع TLS للوصول عبر الشبكة المحلية أو على خادم مستضاف ذاتيا. في كلتا الحالتين، تبقى حدود الثقة واحدة: لا تغادر كلمة المرور الرئيسية وبياناتك أبدا الذاكرة المحمية للخدمة.

## الميزات

**الخزنة الأساسية**
- تنظيم بيانات الاعتماد في مجلدات، مع إعادة الترتيب بالسحب والإفلات
- تخزين كلمة المرور وسر TOTP والملاحظات والحقول المخصصة لكل بيانات اعتماد
- تقييم قوة كلمة المرور، واكتشاف إعادة الاستخدام، واكتشاف كلمات المرور الشائعة
- فحص التسريبات دون اتصال، باستخدام مرشح Cuckoo محلي مبني من قاعدة بيانات كلمات المرور المخترقة في Have I Been Pwned، دون أي طلب شبكة عند كل فحص
- عرض حاملي الأصول: قائمة موحدة لكل عنوان بريد إلكتروني ورقم هاتف ومفتاح أمان مادي مسجل ضمن بيانات اعتمادك

**المصادقة والمصادقة متعددة العوامل**
- دعم WebAuthn وFIDO2 لمفاتيح الأمان المادية ومصادقات المنصة (Touch ID، Windows Hello)
- توليد TOTP (وفق RFC 6238) وHOTP (وفق RFC 4226)، مع حماية من إعادة التشغيل
- تسجيل دخول دون كلمة مرور عبر مفاتيح مرور متزامنة أو مرتبطة بالجهاز
- فرض المصادقة متعددة العوامل قابل للتهيئة لكل حساب

**أوضاع الأمان**
- وضع الإكراه: فتح القفل بكلمة مرور بديلة محددة مسبقا يُشغِّل محوا جنائيا بدلا من منح الوصول
- وضع السفر: يُخفي مجموعة مختارة من بيانات الاعتماد خلف كلمة مرور منفصلة قبل عبور حدود أو تسليم جهاز
- قفل بتأخير أُسِّي بعد محاولات فتح فاشلة متكررة
- الوصول الطارئ: امنح جهة اتصال موثوقة وصولا مؤجلا زمنيا إلى خزنتك في حال أصبحت غير قابل للوصول

**الاستيراد والتصدير**
- صيغة `.p2w` الأصلية: تصدير مشفر بطبقتي AEAD، مع حشو وإخفاء للبيانات الوصفية، مصمم لمقاومة العبث دون اتصال وتحليل حركة البيانات
- تصدير واستيراد بصيغة JSON عادية وCSV وXML متوافق مع KeePass
- استيراد من تصديرات Bitwarden وون باسورد (CSV، 1PUX) وNordPass

**التشفير ما بعد الكمي والمعياري**
- تغليف مفتاح هجين X25519 + ML-KEM-768/1024 (مُفعَّل افتراضيا، وليس خيارا منفصلا يجب تفعيله)
- توقيعات ما بعد كمية ML-DSA-87
- اشتقاق المفاتيح بـ Argon2id، وتشفير موثَّق بـ AES-256-GCM وXChaCha20-Poly1305
- وضع CNSA 2.0 الصارم اختياري، يقصر الخدمة على مجموعة خوارزميات الأمان القومي التجاري الخاصة بوكالة الأمن القومي الأمريكية (HKDF-SHA-384، PBKDF2-SHA-512، وإزالة BLAKE3 وSHA3 وXChaCha20 وEd25519 وX25519 من مسارات الكود النشطة)

## البنية المعمارية

الخدمة تعرض بروتوكول طلبات واستجابات محكم النوع (`daemon/src/ipc/protocol.rs`)، يُنقَل كإطارات MessagePack عبر مقبس يونكس. يحمل كل طلب مُصادَق عليه رمز جلسة تتحقق منه الخدمة قبل الوصول إلى قاعدة البيانات. تتحقق الخدمة أيضا من هوية العملية المتصلة على مستوى نظام التشغيل (`SO_PEERCRED`)، بحيث لا يستطيع الوصول إليها سوى وسيط الويب الموثوق، العامل تحت مستخدم النظام الصحيح.

لا تتلقى طبقة الويب أبدا مفتاحا رئيسيا، أو مفتاح تشفير مفتاح، أو مفتاحا رئيسيا للخزنة، أو مفتاح تشفير بيانات، بأي شكل من الأشكال. تتلقى نصا مشفرا وتُمرِّره. تتابع خدمة مراقبة مرافقة (`monitor/`) نمو الذاكرة واستخدام القرص وسلامة العمليات بشكل مستقل عن خدمة الخزنة نفسها، بحيث يُكتشَف تسرب الذاكرة أو توقف العملية ويُبلَّغ عنه بدلا من أن يتدهور الخدمة بصمت.

التفاصيل التقنية الكاملة، بما في ذلك تسلسل اشتقاق المفاتيح ومواصفات صيغة ملف P2W ونموذج التهديد، موثقة في [`architecture.md`](../../architecture.md).

## نموذج الأمان

يفترض PWDnow أن الشبكة وعملية المتصفح ونظام التشغيل المضيف جميعها معادية بشكل محتمل، ويبني بنيته المعمارية بناء على هذا الافتراض بدلا من افتراض أكثر تساهلا.

- **معرفة صفرية بالتصميم**: لا يمكن للمتصفح تسريب ما لم يمتلكه قط. المفاتيح الرئيسية والمفاتيح المشتقة توجد فقط داخل مساحة ذاكرة الخدمة.
- **حماية الذاكرة**: يُحفظ المفتاح الرئيسي للخزنة في منطقة ذاكرة مؤمَّنة (`mlock`)، تُختَم بـ `mprotect(PROT_NONE)` أثناء الخمول، وتُمحى باستخدام حزمة `zeroize` بمجرد عدم الحاجة إليها.
- **التشفير أثناء السكون**: قاعدة بيانات الخزنة مشفرة من طرف إلى طرف بـ SQLCipher. تستخدم عمليات التصدير تشفيرا موثَّقا مزدوجا (طبقة داخلية AES-256-GCM وطبقة خارجية XChaCha20-Poly1305)، مع ربط الترويسة بكلتا علامتَي المصادقة.
- **التحقق المستقل**: يُشغِّل المشروع باستمرار اختبارات الطفرات واختبارات الفوضى ضمن تكامله المستمر، إضافة إلى مجموعات الاختبار الوحدوية والشاملة المعتادة، خصيصا للكشف عن الاختبارات التي تنجح دون التحقق فعليا من السلوك الذي تدعي تغطيته.

إذا وجدت ثغرة أمنية، يرجى مراجعة [سياسة الأمان](#سياسة-الأمان) قبل فتح تذكرة عامة.

## المنصات المدعومة

يُطوَّر PWDnow ويُختبر بشكل أساسي على **Ubuntu 26.04 LTS (Resolute)**. كما يكتشف المثبت ويدعم:

- Debian والتوزيعات المشتقة منه (Ubuntu، Linux Mint، Pop!_OS، Zorin، Kali)
- Fedora وتوزيعات عائلة RHEL (Fedora، RHEL، CentOS، Rocky Linux، AlmaLinux)

تدعم سلسلة أدوات Rust كلا من `x86_64` و`aarch64`. قد تعمل توزيعات لينكس أخرى لكنها ليست جزءا من مصفوفة الاختبار المنتظمة. لا توجد حاليا نسخة بناء لنظامَي macOS أو Windows.

## البدء

### التثبيت السريع

```bash
git clone https://github.com/PWDnow/PWDnow-password-manager.git
cd PWDnow
./install.sh
```

يكتشف المثبت توزيعتك، ويتحقق من التبعيات الناقصة ويعرض تثبيتها، ويدقق إعدادات SSH لديك، ويتحقق من تعارضات المنافذ، ويبني الخدمة وواجهة الويب من المصدر، ويثبت كليهما كخدمات systemd تعمل تحت مستخدمَي نظام مخصصين وغير مُميَّزَين. لا يُثبَّت شيء بامتيازات مرتفعة تتجاوز ما يتطلبه systemd وAppArmor وتثبيت الحزم، وتُعرَض كل خطوة مُميَّزة قبل تنفيذها.

### البناء من المصدر

المتطلبات: Node.js إصدار 20 أو أحدث، Rust إصدار 1.94 أو أحدث (مُثبَّت في `daemon/rust-toolchain.toml`)، `protoc`، وترويسات التطوير لـ `libsodium` وsqlcipher وlibfido2.

```bash
# الخدمة
cd daemon
cargo build --release
cargo test

# الويب
cd web
npm install
npm run build
npm start
```

أو، من المجلد `deploy/`:

```bash
make build          # الخدمة + الويب، وضع الإصدار
make test            # cargo test + vitest
make install          # تثبيت الملف الثنائي ووحدات systemd وملف AppArmor وإعداد nginx (يتطلب sudo)
```

تغليف المفتاح ما بعد الكمي مُفعَّل افتراضيا. يبقى `make build-pq` و`cargo build --release --features pq-hybrid-1024` كاسمين بديلين صريحين لنفس البناء الافتراضي، من أجل الوضوح والتوافق مع التوثيق الأقدم. استخدم `--features cnsa-strict` لوضع CNSA 2.0 الصارم.

### الإعداد

انسخ `web/.env.example` إلى `web/.env` واضبطه حسب الحاجة:

| المتغير | الغرض |
|---|---|
| `DAEMON_GRPC_ADDR` | العنوان الذي تستخدمه طبقة الويب للوصول إلى الخدمة (افتراضيا `127.0.0.1:50051`) |
| `VAULT_ORIGIN` | أصل المتصفح المسموح به في بيئة الإنتاج، يُستخدم للتحقق من أصل WebSocket |
| `BIND_HOST` | الواجهة التي يستمع عليها خادم الويب (افتراضيا `127.0.0.1`؛ اضبطه على `0.0.0.0` للوصول عبر الشبكة المحلية) |
| `SSL`، `SSL_PORT`، `SSL_DIR` | HTTPS اختياري موقَّع ذاتيا، يُولَّد بواسطة `web/scripts/generate-ssl.sh` |

## الاستخدام

عند التشغيل الأول، يُرشدك `Setup.tsx` خلال إنشاء الخزنة: اختيار كلمة مرور رئيسية، وتسجيل اختياري لمفتاح أمان مادي أو TOTP، وتُنشئ الخدمة قاعدة بيانات SQLCipher مشفرة إضافة إلى ملف مرافق بصيغة واضحة يسجل فقط ما تحتاجه صفحة تسجيل الدخول (أي طرق مصادقة متعددة العوامل مُهيَّأة، وهل تسجيل الدخول بكلمة المرور مُفعَّل أصلا)، بحيث لا يحتاج أي شيء لفك التشفير قبل مصادقتك.

من هناك:

- نظّم بيانات الاعتماد في مجلدات، وأضف حقولا مخصصة، وولِّد كلمات مرور قوية في الموضع نفسه
- فعِّل وضع الإكراه ووضع السفر من الإعدادات إذا أردت القدرة على إظهار حالة آمنة ومعقولة تحت الإكراه أو عند عبور حدود
- شغِّل مراقب التسريبات المدمج لفحص كلمات المرور المحفوظة مقابل نسخة محلية دون اتصال من كلمات المرور المخترقة المعروفة، دون أي استعلام صادر لكل كلمة مرور
- صدِّر ملف `.p2w` للنسخ الاحتياطي، أو استورد من مدير كلمات مرور آخر، دون مغادرة جهازك أبدا

## التطوير

هيكل المستودع:

```
PWDnow/
├── daemon/     خدمة الخزنة بلغة Rust. كل التشفير موجود هنا.
├── web/        واجهة أمامية React 19 + Express ووسيط IPC.
├── monitor/    عملية Rust مستقلة لمراقبة الصحة واكتشاف تسرب الذاكرة.
├── deploy/     وحدات systemd، ملف AppArmor، إعداد Nginx، Makefile.
├── proto/      تعريفات gRPC/protobuf المشتركة بين الخدمة والويب.
└── hibp/       سكربت يبني مرشح Cuckoo الخاص بـ HIBP دون اتصال.
```


## الاختبار

```bash
# الخدمة
cd daemon && cargo test
cargo test -- <test_name>       # تشغيل اختبار واحد

# اختبارات الوحدة للويب
cd web && npm run test
npx vitest run src/utils/crypto.test.ts   # ملف واحد

# اختبارات شاملة (Playwright)
cd web && npx playwright test
npx playwright test e2e/comprehensive-platform.spec.ts   # جولة انحدار كاملة
```

يشغِّل التكامل المستمر اختبارات الوحدة، والاختبارات الشاملة، وتدقيق التبعيات، واختبارات الطفرات، واختبارات الفوضى عند كل دفعة وطلب سحب. يُعد `web/e2e/comprehensive-platform.spec.ts` بوابة الانحدار: يمر عبر المصادقة (مسارات النجاح والفشل)، والتنقل، وعمليات إنشاء وقراءة وتحديث وحذف المجلدات وبيانات الاعتماد، ووضع الإكراه، وإتلاف الحساب، ويجب أن ينجح قبل إطلاق أي تغيير في الواجهة الأمامية أو المصادقة.

## النشر

لأي استخدام يتجاوز جهازا محليا واحدا، ضع Nginx أمام عملية Express:

- يتولى `deploy/nginx/vault.conf` إنهاء TLS وHSTS وتحديد المعدل. يجب ألا يضبط Nginx ترويسة Content-Security-Policy الخاصة به، لأن خادم Express يُدرج رمز nonce جديدا مع كل طلب.
- يشغِّل `deploy/vault-daemon.service` الخدمة تحت مستخدم نظام مخصص باسم `vault`، مع `MemorySwapMax=0` و`NoNewPrivileges` و`PrivateTmp`، وفقط قدرة `CAP_IPC_LOCK` التي يحتاجها لتأمين الذاكرة.
- يحصر `deploy/apparmor.d/vault-daemon` وصول الخدمة إلى نظام الملفات والقدرات على مستوى النواة، ويُطبَّق دون تعديل على مضيفَي `x86_64` وaarch64 على حد سواء.

يربط `make install` (أو `install.sh` لتثبيت موجَّه كامل) كل هذا معا، بما في ذلك تحميل ملف AppArmor وتفعيل وحدات systemd.

## سياسة الأمان

يتعامل PWDnow مع بيانات الاعتماد، لذا فإن تقرير الثغرات هنا أهم منه في معظم المشاريع. إذا وجدت مشكلة أمنية، يرجى عدم فتح تذكرة عامة. بدلا من ذلك، استخدم الإبلاغ الخاص عن الثغرات في GitHub لهذا المستودع، أو تواصل مباشرة مع القائمين على الصيانة. أرفق تفاصيل كافية لإعادة إنتاج المشكلة، وإن أمكن، تقييما للأثر. سنؤكد استلام التقارير بسرعة وننسب الفضل لمن يرغب في ذلك بمجرد إصدار الإصلاح.

## المساهمة

التذاكر وطلبات السحب مرحب بها. قبل إرسال أي تغيير:
